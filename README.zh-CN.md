## 制作你的影片

### 1 / 直接告诉 Agent，你想拍什么

克隆后，在 Codex 或你使用的编程 Agent 中打开 **codex-film-studio** 文件夹。
直接发送创作要求即可。工具选择、独立项目创建、环境准备和制作，都由 Agent 完成，
不需要你手动执行命令。

> 请用 Mid-century Cartoon 风格，为[目标观众]制作一部关于[主题]的三分钟视频，
> 使用英文配音和字幕。请你读取工作室的制作指南，自动创建独立项目并准备环境，
> 完成脚本、绘画、动画和声音。检查最终画面、运动和音轨，修复发现的问题，
> 交付 1080p MP4 和可编辑工程，并说明实际检查范围。

把风格、主题、观众、语言和时长换成你的要求。也可以直接提供某个 Style 页的链接，
或让 Agent 根据故事选择合适的风格。

<details>
<summary><b>还没有克隆？把这段话发给 Agent。</b></summary>

> 请将 https://github.com/visiontrail/codex-film-studio.git 克隆到新的文件夹，
> 不覆盖已有文件。读取 AGENTS.md 和 codex-film 技能，然后根据我的创作要求
> 制作影片。环境准备和命令执行请你完成。

</details>

### 2 / 想复刻原样片，也直接说

> 请原样复刻[风格]中的[样片标题或链接]。请你查找可用的原始工程、素材和配音，
> 自动完成独立项目创建、环境准备、渲染与检查，交付 MP4 和可编辑工程。
> 如果缺少原始工程或素材，请明确告诉我缺什么，不要用新编内容代替原片。

原样复刻需要原始构图与输入素材。Agent 可使用已发布的白板样片输入；其他样片需要
可用的外部源工程包。展示页的成片下载包可能不包含这些源文件。
[复现方法](methods/reproduction.md)说明了 Agent 应检查的内容。

### 3 / 看成片，再提出修改

Agent 会读取 [`codex-film` 技能](.agents/skills/codex-film/SKILL.md)、
[导演指南](DIRECTOR.md)、[技术指南](TECHNIQUE.md)和所选风格规范，完成制作流程。
每部新片都放在风格库之外的独立工程中，已有项目会被保留。交付包含成片、可编辑工程
和实际检查范围。

在同一个对话里继续提出要求，例如“开头慢一点”“旁白更亲切一些”或“改成竖屏构图”。
Agent 会一起调整画面、旁白、字幕和声音。

Agent 会检查制作环境与可用的配音工具。确实需要你提供图片、录音或配音服务访问权限时，
会说明具体缺少什么。本地浏览也可以直接让 Agent 打开工作室；技术细节见
[本地网页说明](docs/pages.md#local-style-catalog)。

<details>
<summary><b>Agent 技术参考：白板样片重建命令</b></summary>

以下命令由 Agent 在仓库根目录执行：

```sh
python3 scripts/fetch_demo.py --edition short
cd styles/whiteboard/studio
npm ci
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 先生成画面预览，再完整合成配音、音乐和笔触音效。
node scripts/render.mjs --start 0 --end 8 --width 960 --out media/preview.mp4
.venv/bin/python scripts/build.py --skip-atlases
python3 scripts/serve.py
```

打开 **http://127.0.0.1:8246/**。完整输出位于
`styles/whiteboard/studio/media/does-ai-help-you-learn-3min.mp4`。

在仓库根目录执行 `python3 scripts/fetch_demo.py --edition all` 下载两版样片及配音。
长版构建命令添加 `--edition long`，输出在
`editions/long/media/does-ai-help-you-learn-long.mp4`。

Git 包含源码、字体和乐器采样；影片、配音 WAV 与时间数据从固定版本的 Release
下载并校验 SHA-256。克隆本身不会下载影片。复现保留原构图与输入音频；不同的
渲染器和编码器版本可能生成不同的文件字节。

已在 Apple Silicon macOS、Node 24 和 FFmpeg 8 上验证。Linux CI 会渲染一段
画面预览；Windows 的语音客户端使用 WSL。

</details>

<details>
<summary><b>部署公开展示页</b></summary>

部署自己的 fork：在 **Settings → Pages → Source** 选择 **GitHub Actions**，
然后在 Actions 中运行 **Deploy film showcase**。推送到 `main` 也会触发部署。
构建会下载并校验固定版本的 Release 资源，发布明确列出的首页、目录、预览图和播放器文件。
详见[部署与本地预览说明](docs/pages.md)。

公开展示页通过校验过的 Release 资源包播放网络预览，本地页面继续使用保留工程的原片。
发布其他影片需要明确请求。

</details>

## 扩展这个风格库

所有视觉风格位于 `styles/<id>/`，由 [styles.json](styles.json)记录完成状态与能力；
跨风格通用流程放在 `methods/`。

向库内贡献可复用的视觉规则、通用工具和空白输入。每部影片的故事、肖像、媒体与
审阅记录放在外部项目。指定真实人物时，使用为新影片提供的肖像。
目录规范见 [CONTRIBUTING.md](CONTRIBUTING.md)。

登记风格后，运行 `python3 scripts/update_style_index.py`，同步中英文首页和详细目录。
使用 `--check` 检查是否遗漏更新。

<details>
<summary>继续使用旧项目</summary>

原 `methods/<style>/` 已迁入 `styles/<style>/`，`--method <id>` 保留为
`--style <id>` 的兼容别名。已创建的项目是独立副本，可以原地继续。
已发布样片和保留的展示入口维持原有构图。

</details>
