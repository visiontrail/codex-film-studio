# Chatterbox、时间对齐与听审

使用自己的 Chatterbox 服务，或导入已生成的逐句 WAV。方法库不含服务
地址、声音 ID、凭据、旧提供者任务或上一部片的配音。新项目自行实现适配器。

仓库已有服务合同可参考：`GET /v1/capabilities` 返回字符上限、服务指纹和
声音列表；`POST /v1/jobs` 建立任务；带认证轮询 `GET /v1/jobs/{id}`；完成后
从 `GET /v1/jobs/{id}/audio` 获取 WAV。该合同是一个部署的 API，不能假设
任何安装的 Chatterbox 都支持。请求使用环境中的认证信息和幂等键，先核实
实际 capabilities。不要猜测 `/v1/audio/jobs/...` 路径。

每条稳定 line ID 保存准确源文、声音/模型/部署指纹、生成参数与请求摘要，
并将结果绑定到原始 WAV 的 SHA-256。保存任务 ID 和重试证据于外部项目的
私有记录。重试未知结果先查询原任务；只有源文与所有配置一致才能复用缓存。
新修复保留旧录音，禁止偷偷替换同名文件后沿用旧的验收记录。

测量解码后的采样数、采样率、时长、静音和削波。独立转写不要先塞入待验证
源文诱导识别；将差异定位到行和时间点。数字/缩写的等价读法可以明确登记，
漏词、添词或关键词错误则修复实际音频。存在疑义时听审或用独立识别器复核
同一个 WAV 哈希。限制有理由的重试次数，未解决问题如实保留。

源文用于字幕文本，实际语音用于时间对齐。保持 cue 顺序与完整覆盖，确认
句尾未被镜头结束裁断；不要为了凑时长压缩旁白。长篇每章之间留自然呼吸。
ASR 对齐、波形检查、播放器进度变化都不证明人已经听过声音。

音乐、拟音和旁白分轨；按语句包络压低配乐。−14 LUFS 与约 −1.2 dBTP 可作
网络视频的项目目标起点，成片编码后重新测量；不把目标值冒充测量值。
实际听过后才评价音色、自然度、点击声、噪声与音乐/人声平衡。听审工具或
输入能力缺失时将其记为未完成，不自动通过。
